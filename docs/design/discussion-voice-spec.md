# Engram 讨论语音输入与文字转语音 Spec

> 状态：Proposal，待产品确认
> 日期：2026-08-19
> 范围：仅定义产品、交互与技术协议，本阶段不开发
> 关联文档：[学习模式产品与交互 Spec](./learning-mode-spec.md)

## 1. 背景与问题

当前讨论课只支持文字输入和文字回复。用户需要先阅读 AI 问题、键盘输入答案，再阅读 AI 反馈，交互更像聊天，而不是和英语老师对话；这也让用户更容易把注意力放在拼写和编辑上，弱化了即时组织语言与听说练习。

本能力要让用户可以：

1. 直接说出英文答案，并在发送前看到、修改识别文本；
2. 自动听到 AI 老师的问题、反馈、提示和课堂总结；
3. 在语音能力不可用时继续完整使用现有文字讨论。

本 Spec 经确认后，覆盖主 Spec“首版暂不支持语音输入”的限制；其他讨论状态机、提纲顺序、字幕引用和会话协议保持不变。

## 2. 产品决策

首版采用浏览器提供的 Web Speech API，不新增 Engram 云端语音接口：

- 语音输入使用 `SpeechRecognition`，兼容 Chrome 的 `webkitSpeechRecognition` 前缀实现；
- 文字转语音使用 `speechSynthesis` 和 `SpeechSynthesisUtterance`；
- 识别出的最终文本继续走现有 `DISCUSS_LEARNING_MATERIAL` 文字讨论协议；
- Engram 后端不接收、不保存原始录音，也不生成或缓存音频文件；
- 浏览器可能在本机或通过浏览器供应商的远程服务完成识别与合成，界面必须在首次使用前说明这一点；
- 所有语音能力都按运行时特性检测渐进增强，不得成为讨论课的前置条件。

选择该方案的原因是当前产品只支持 Chrome 桌面扩展，现有 AI 代理也只有文字能力。首版先验证语音交互是否提升讨论完成率，避免同时引入第二套 API Key、音频上传、文件格式、计费和数据保留链路。

若后续数据显示浏览器识别准确率或声音自然度不达标，再以相同前端状态机替换为云端 STT/TTS；这不属于本期。

## 3. 目标与非目标

### 目标

- 用户点击一次麦克风即可开始说英文，停止后获得可编辑文本；
- AI 新回复默认自动朗读，用户可随时停止或重播任意一条 AI 消息；
- 录音、AI 朗读和左侧视频声音不重叠，避免回声和注意力冲突；
- 权限拒绝、识别失败、朗读失败和 API 不支持均有明确反馈，文字讨论不受影响；
- 不改变现有讨论轮次、AI Prompt、消息上限、字幕证据和课程完成规则；
- 桌面最窄 300px 学习面板和 390px 移动宽度下均可操作。

### 非目标

- 实时双工通话、AI 与用户同时说话或自动抢话；
- 免点击的连续会话、唤醒词或后台持续监听；
- 自动发送识别结果；
- 发音评分、口音判断、音素级反馈或录音回放；
- 选择麦克风设备、降噪参数或声音角色；
- 保存录音、导出音频或同步语音历史；
- 中文、混合语言及英语以外语言的识别质量保证；
- Firefox、Safari 或其他浏览器支持承诺；
- 新增云端 STT、TTS 或 Realtime 服务。

## 4. 核心用户流程

### 4.1 开始讨论

1. 用户点击“开始讨论”；
2. 客户端暂停左侧视频，但不在讨论结束后自动恢复；
3. 第一条 AI 问题正常显示；
4. “自动朗读”默认开启时，立即朗读第一条问题；
5. 用户可点击麦克风回答，也可直接键盘输入。

“开始讨论”属于明确的用户手势，可用于启动浏览器音频能力。进入讨论不立即请求麦克风权限；只有用户第一次点击麦克风时才请求。

### 4.2 语音回答

1. 用户点击输入框内的麦克风按钮；
2. 若 AI 正在朗读，先立即停止朗读；若视频正在播放，先暂停视频；
3. 首次使用展示简短说明，并由浏览器请求麦克风权限；
4. 状态变为“正在听，请用英文回答…”；麦克风按钮显示录音中状态；
5. 浏览器返回的临时识别结果实时显示在输入框中，但不进入消息历史；
6. 用户再次点击麦克风，或浏览器判定本次发言结束后，停止识别；
7. 最终文本保留在输入框中，状态变为“已识别，可编辑后发送”；
8. 用户可修改文本，点击现有发送按钮后才正式提交。

如果输入框在录音前已有文字，识别结果追加到当前光标位置，并自动处理英文空格；不得覆盖用户原稿。识别过程中输入框只读，停止后恢复编辑。

不自动发送是首版的明确约束：识别错误不能未经用户确认就消耗一个讨论轮次或触发 AI 请求。

### 4.3 AI 朗读

- “自动朗读”开启时，每次新增 AI 主消息后朗读该消息正文；
- 问题、反馈、提示和课堂总结都属于可朗读正文；
- 不朗读“AI 老师”角色标签、字幕时间戳、引用原文按钮和独立的 `feedback-note`；
- AI 一条消息同时包含反馈和下一题时，按界面正文顺序完整朗读；
- 每条 AI 消息角色标签旁显示朗读按钮：空闲时为“朗读这条回复”，朗读当前消息时为“停止朗读”；
- 同一时刻最多存在一个朗读任务；开始新朗读前必须清空旧队列；
- 用户点击麦克风、播放左侧视频、切换离开讨论 Tab、完成/重置讨论或页面隐藏时，立即停止朗读；
- 朗读失败只显示轻量错误，不影响文字内容和下一轮讨论。

首版使用系统可用的英语声音：优先选择语言精确匹配 `en-US` 的默认声音，其次选择任意 `en-*` 声音，最后使用浏览器默认声音。默认参数为 `rate = 0.95`、`pitch = 1`、`volume = 1`，本期不提供声音和语速设置。

### 4.4 视频声音协调

- 开始讨论时暂停视频；
- 开始识别或朗读前再次确保视频已暂停；
- 用户在识别期间主动播放视频时，停止识别并保留已有最终文本；
- 用户在朗读期间主动播放视频时，停止朗读；
- 系统不自动恢复视频，避免讨论中突然出现背景声。

## 5. 界面规格

### 5.1 Composer

现有输入区增加两类控制：

```text
[🔊 自动朗读：开]                              [给我提示]
┌─────────────────────────────────────────────────────┐
│ 用英文回答…                            [🎙] [发送] │
└─────────────────────────────────────────────────────┘
  正在听，请用英文回答…
```

- “自动朗读”与“给我提示”位于输入框上方的同一操作行；
- 麦克风按钮位于发送按钮左侧，两个按钮均为 34×34px；
- 输入框右侧为两个按钮预留空间，文字不得被遮挡；
- 麦克风空闲态使用中性色，录音态使用琥珀色实心或描边并配合“正在听”文字，不得只靠颜色表达；
- 录音态可以使用轻微脉冲动画，但必须尊重 `prefers-reduced-motion`；
- 输入区下方保留一行固定高度状态区域，避免状态变化引起布局跳动；
- 朗读开关采用按钮或 checkbox 语义，显示文字，不只使用扬声器图标。

### 5.2 AI 消息

AI 消息的角色行调整为：

```text
AI 老师                                      [🔊]
┌─────────────────────────────────────────────────────┐
│ What is your number one bucket list destination?   │
└─────────────────────────────────────────────────────┘
```

- 扬声器按钮点击热区至少 28×28px；
- 正在朗读的消息显示停止图标和 `aria-pressed="true"`；
- 用户消息不提供朗读按钮；
- 自动朗读关闭时，单条消息朗读按钮仍可使用。

### 5.3 文案与可访问性

| 状态 | 可见文案 | 麦克风 `aria-label` |
| --- | --- | --- |
| 空闲 | 空 | 语音回答 |
| 请求权限 | 正在请求麦克风权限… | 正在请求麦克风权限 |
| 录音中 | 正在听，请用英文回答… | 停止语音输入 |
| 收尾中 | 正在完成识别… | 正在完成语音识别 |
| 已完成 | 已识别，可编辑后发送 | 重新语音回答 |
| 未听到语音 | 没有听清，请再试一次 | 重新语音回答 |
| 权限拒绝 | 麦克风未授权，请在浏览器设置中允许 | 麦克风未授权 |
| 不支持 | 当前浏览器不支持语音输入，可继续打字 | 当前浏览器不支持语音输入 |

状态区使用 `aria-live="polite"`，但临时识别文本变化不逐字播报，避免屏幕阅读器噪声。所有控制支持键盘操作和清晰的 `:focus-visible` 样式。

## 6. 状态模型与并发规则

### 6.1 输入状态

`voiceInputState` 只能为：

```text
unavailable → idle → requesting_permission → listening → finalizing → idle
                                  ↘ error → idle
```

- `unavailable`：API 不存在或被 Permissions Policy 阻止；
- `requesting_permission`：等待浏览器授权结果；
- `listening`：接收临时和最终识别结果；
- `finalizing`：已经要求停止，等待最后一个结果或 `end`；
- `error`：显示错误后可重试，不清空已有输入。

单次语音输入最长 120 秒；到时自动停止并保留已获得文本。页面在 `hidden`、`pagehide` 或讨论重置时调用 `abort()`，临时结果不保留，已有最终结果保留在输入框。

### 6.2 输出状态

`speechOutputState` 只能为：

```text
unavailable | disabled | idle | speaking | error
```

“自动朗读”是会话偏好，不等于 API 可用性。自动朗读关闭时状态为 `disabled`，用户单条重播期间仍临时进入 `speaking`。

### 6.3 互斥规则

互斥原则固定为：用户新触发的录音或视频播放动作覆盖旧音频动作，AI 自动朗读优先级最低。录音与视频播放不能共存，二者以后触发的用户动作生效。

| 新动作 | 当前识别中 | 当前朗读中 | 当前 AI 请求中 |
| --- | --- | --- | --- |
| 点击麦克风 | 停止并收尾 | 先停止朗读，再开始识别 | 禁用，不允许开始 |
| 播放视频 | 停止并保留最终文本 | 停止朗读 | 允许，AI 请求继续 |
| 单条朗读 | 禁用 | 切换到所选消息 | 允许朗读已有消息 |
| 发送答案 | 先完成识别后才可发送 | 停止朗读 | 已禁用，避免重复提交 |
| 获取新 AI 消息 | 不应同时发生 | 清空旧朗读并朗读新消息 | 请求结束 |

`discussionInput`、发送按钮、“给我提示”和麦克风按钮在 AI 请求期间统一禁用；请求结束后按讨论是否完成恢复。

## 7. 技术设计

### 7.1 前端边界

建议新增一个不依赖 DOM 的语音适配层 `src/discussion-speech.js`，统一封装：

- `isRecognitionSupported()`；
- `startRecognition({ lang, onInterim, onFinal, onStateChange, onError })`；
- `stopRecognition()` / `abortRecognition()`；
- `isSynthesisSupported()`；
- `speak({ text, lang, rate, onStart, onEnd, onError })`；
- `cancelSpeech()`；
- 英语声音选择和 `voiceschanged` 的异步处理。

`learning-mode.js` 只负责把语音状态接入现有讨论状态机、输入框和消息列表，不直接散落浏览器语音 API 事件处理。适配层通过依赖注入接受 `SpeechRecognition` 和 `speechSynthesis`，便于单元测试与预览模式替身。

### 7.2 识别参数

```js
recognition.lang = "en-US";
recognition.continuous = false;
recognition.interimResults = true;
recognition.maxAlternatives = 1;
```

运行时若支持 `SpeechRecognition.available()` 和 `processLocally`，且本机已有 `en-US` 语言包，则优先使用本地识别；本期不自动下载语言包。否则允许浏览器选择本地或远程识别。所有扩展属性必须先做特性检测，不得影响最低 Chrome 版本上的基础功能。

客户端只采纳 `result[0].transcript`；`confidence` 仅可用于调试，不用于阻止用户提交，也不显示伪精确评分。

### 7.3 iframe 与权限

学习面板是 YouTube 页面内的跨源 `chrome-extension://` iframe。创建 iframe 时需要把现有：

```html
allow="clipboard-write"
```

扩展为至少：

```html
allow="clipboard-write; microphone"
```

若目标 Chrome 版本支持本地识别 Permissions Policy，再按特性检测加入 `on-device-speech-recognition`。实现阶段必须在真实 YouTube 学习模式中验证父页面策略没有阻断扩展 iframe；不能只在 `learning-mode.html?preview=1` 顶层页面验证。

麦克风权限只在用户点击麦克风后由浏览器请求，不新增宽泛的 Manifest 权限，也不使用 `contentSettings` 代替用户授权。权限被永久拒绝后不循环弹窗。

### 7.4 消息和服务端协议

服务端协议不变。最终识别文本按现有格式进入消息历史：

```json
{ "role": "user", "content": "My number one destination is Iceland." }
```

以下数据不得加入 `state.messages`，也不得发送给代理：

- 原始音频；
- 临时识别文本；
- 识别置信度；
- 麦克风设备信息；
- 朗读状态与声音名称。

现有 1,200 字符输入上限继续生效。语音结果超出剩余长度时，只保留可容纳文本并提示“回答已达到 1200 字符上限”。

### 7.5 设置

新增 `discussionAutoSpeak` 布尔设置，存入 `chrome.storage.sync`：

- 新用户默认 `true`；
- 用户切换后立即生效并持久化；
- 从 `true` 切到 `false` 时立即停止当前朗读；
- 设置读取失败时只对当前会话使用默认值，不阻塞讨论。

麦克风权限、识别方式和声音对象不写入扩展存储。

### 7.6 预览模式

`learning-mode.html?preview=1` 不请求真实麦克风权限，也不依赖系统声音：

- 点击麦克风后按固定时序演示 `listening → finalizing → idle`；
- 向输入框写入固定英文示例，不自动发送；
- 点击朗读按钮只演示 `speaking` 视觉状态，可在短延迟后结束；
- 自动化截图和交互测试不产生真实声音。

## 8. 隐私与安全

首次点击麦克风前显示一次简短说明：

> Engram 不保存录音。语音识别由浏览器提供，音频可能由浏览器服务商处理。你也可以继续打字回答。

用户确认后再调用语音识别。该说明是否已经展示可存入本地布尔值，但“已说明”不能替代浏览器麦克风授权。

- Engram 自建代理不接收音频；
- 不记录识别中间结果、置信度、设备名称或音频时长到日志；
- 错误日志只记录稳定错误码，不包含用户口述内容；
- 页面隐藏、离开讨论或扩展上下文失效时立即停止采集；
- 不允许字幕、题目或 AI 回复改变语音权限、自动监听或数据发送规则。

## 9. 错误与降级

| 场景 | 用户反馈 | 降级行为 |
| --- | --- | --- |
| 无 `SpeechRecognition` | 当前浏览器不支持语音输入，可继续打字 | 隐藏或禁用麦克风；文字讨论完整可用 |
| 麦克风被 Permissions Policy 阻止 | 当前页面无法使用麦克风，可继续打字 | 不重复请求；保留文字输入 |
| 用户拒绝权限 | 麦克风未授权，请在浏览器设置中允许 | 不清空草稿；可继续打字 |
| 没有检测到语音 | 没有听清，请再试一次 | 回到空闲；不发送空消息 |
| 识别网络错误 | 语音识别暂时不可用，请稍后再试 | 保留最终文本；文字输入可用 |
| 录音设备不可用 | 没有找到可用麦克风 | 保留草稿；文字输入可用 |
| 120 秒到时 | 已停止录音，可编辑后发送 | 提交已获得的最终文本到输入框 |
| 无 `speechSynthesis` 或无声音 | 当前设备暂不支持朗读 | 自动朗读关闭；文本正常显示 |
| 合成中断或失败 | 朗读失败，可重试 | 清理 speaking 状态；不重发 AI 请求 |

统一错误处理必须区分用户主动 `abort` 和真正失败；主动停止不得显示红色错误。

## 10. 监测指标

本期只记录不含内容的本地聚合事件；若项目尚无遥测基础设施，则保留事件接口而不发送到外部：

- `voice_input_started`；
- `voice_input_completed`；
- `voice_input_failed` + 稳定错误码；
- `voice_input_sent`；
- `tts_auto_started`；
- `tts_replay_started`；
- `tts_stopped` / `tts_failed`；
- 语音讨论完成率与纯文字讨论完成率。

不得记录识别文本、AI 回复、录音、声音名称或权限设置详情。

## 11. 测试策略

### 自动化

- 语音适配层用假 `SpeechRecognition` 覆盖开始、临时结果、最终结果、停止、主动取消、错误和超时；
- 假 `speechSynthesis` 覆盖声音延迟加载、自动朗读、单条重播、切换消息、取消和错误；
- UI 测试验证麦克风、自动朗读、单条朗读按钮、ARIA、禁用态和状态文案；
- 状态机测试验证识别、视频播放、朗读和 AI 请求不会重叠；
- 预览模式测试验证不调用真实语音 API；
- 构建测试验证新脚本进入扩展产物和 `web_accessible_resources`。

### 手工浏览器验收

- 在真实 YouTube 学习页而非独立预览页完成首次授权；
- 分别验证允许、拒绝、永久阻止和无麦克风设备；
- 验证短回答、包含停顿的长回答、空白录音和接近 1,200 字符上限；
- 验证 AI 自动朗读、手动停止、重播旧消息和关闭自动朗读；
- 验证录音/朗读期间播放视频的互斥行为；
- 验证 300px 可调整面板、1440×900 桌面和 390px 移动布局；
- 验证页面隐藏、刷新、退出学习模式和扩展重载后麦克风立即释放。

## 12. 验收标准

### 功能

- 支持的 Chrome 环境中，用户能通过麦克风生成英文文本、编辑并发送；
- 语音识别永不自动发送答案；
- 自动朗读默认开启且可持久关闭；
- 每条 AI 消息可单独朗读、停止和重播；
- 同一时间不会同时录音、播放 AI 朗读和播放视频声音；
- AI 请求期间不能重复发送、开始录音或触发提示请求；
- 权限拒绝或 API 不支持时，文字讨论全过程可完成；
- 讨论完成后所有语音采集与朗读均已停止；
- 预览模式无需权限、网络或真实声音即可走通全部视觉状态。

### 隐私与质量

- 网络检查确认 Engram 代理没有接收音频请求；
- 日志和消息历史中没有原始音频、临时识别文本和置信度；
- 浏览器控制台无相关 error/warn；
- 根目录与服务器既有测试通过，新增语音测试通过；
- 键盘、屏幕阅读器和 `prefers-reduced-motion` 场景可用；
- 300px–桌面宽度内无按钮遮挡、输入文字遮挡或状态跳动。

## 14. 待确认项

本 Spec 推荐以下默认值，确认后按此实现：

1. 首版使用浏览器 Web Speech，不新增云端语音供应商；
2. 自动朗读默认开启，用户可持久关闭；
3. 语音识别结果必须由用户检查并手动发送；
4. 首版识别语言固定为 `en-US`，不提供声音、口音和语速设置；
5. 首次语音使用前展示隐私说明，Engram 后端不接收录音。

## 15. 技术依据

- [W3C Web Speech API Draft Community Group Report](https://w3c.github.io/speech-api/speechapi.html)：定义语音识别、`processLocally` 和语音合成接口；该能力仍需按运行时特性检测，不作为文字讨论的硬依赖；
- [Chrome Permissions Policy](https://developer.chrome.com/docs/privacy-security/permissions-policy)：跨源 iframe 使用麦克风等能力需要显式的 `allow` 委派，并仍受父页面策略约束；
- [Chrome 扩展隐私建议](https://developer.chrome.com/docs/extensions/develop/security-privacy/user-privacy)：敏感能力应在用户实际启用功能时请求，并坚持最小权限原则。
