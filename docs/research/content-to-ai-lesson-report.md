# 从任意英文材料到 AI 互动课

## 英境（Engram）产品研究与方案报告

> 研究日期：2026-08-12<br>
> 目标：把视频、播客、文章和普通网页转换为一套可理解、可练习、可对话、可纠错、可长期复习的个性化英语课。

## 一、结论先行

Engoo Daily News 最值得借鉴的不是页面样式，而是它把一篇真实内容压缩成了一条非常容易理解的学习路径：

**Vocabulary → Article → Discussion → Further Discussion**

这条路径解决了“拿什么学”和“围绕什么聊”，但对自学产品还不够完整。它主要缺少五件事：

1. 学前诊断：这份材料对当前用户是否合适，难点究竟在哪里；
2. 理解检查：用户是看懂了，还是只是顺着翻译读完了；
3. 输出脚手架：不会回答时，怎样从词、句型逐步走到完整观点；
4. 高质量反馈：哪些错误值得纠，什么时候纠，纠完如何让用户重新说一次；
5. 长期记忆：学过的词和表达怎样跨材料再次出现，并在数天后被主动用出来。

因此，英境不应只做“AI 自动生成一份 Engoo 页面”，而应做一个 **AI Lesson Compiler（AI 课程编译器）**：把任何材料编译成一条由输入走向输出、再走向长期记忆的学习闭环。

推荐的完整闭环是：

**导入材料 → 难度诊断 → 首次理解 → 语境精学 → 主动提取 → 内容讨论 → 迁移讨论 → 反馈重说 → 间隔复习 → 跨材料复现**

产品的核心价值可以概括为一句话：

> **不是让用户“看过更多英语”，而是让每一份他真正感兴趣的内容，都留下可以再次理解、主动说出和长期记住的语言资产。**

## 二、Engoo 模式为什么有效

Engoo 官方把 Daily News 描述为：每天选择短新闻，加入实用词汇和讨论问题，并按不同水平提供材料；它也明确建议用户与真人教师一起使用。也就是说，这套页面本质上不是完整的自学系统，而是一份“真人一对一课堂的共享教案”。[Engoo 官方介绍](https://engoo.com/blog/engoo/what-engoo-lesson-materials-are-right-for-you/)

它有效的原因有四点：

- **内容先于知识点。** 用户因为对新闻感兴趣而进入，不是因为今天必须学某个语法章节。
- **长度有限。** 一篇材料能在一次会话中完成，学习阻力低。
- **词汇与上下文绑定。** 单词紧邻文章，不是孤立词表。
- **讨论把输入变成输出。** Article 回答“作者说了什么”，Discussion 回答“你怎么看”，Further Discussion 再把话题迁移到个人经验和更广场景。

但直接照搬会产生三个问题：

- 静态问题可能和用户水平、兴趣、回答内容无关；
- 用户可以一路查看释义和答案，却没有真正进行回忆；
- 讨论结束后没有可追踪的语言增量，下一篇材料又从零开始。

所以英境应保留 Engoo 的**低门槛结构感**，同时在背后加入个性化、动态对话、纠错与记忆系统。

## 三、研究给产品设计的启示

### 1. “认识”不等于“会用”：必须安排主动提取

Karpicke 与 Roediger 以外语词汇为材料的实验发现，在已经学会后继续重复阅读，对延迟回忆帮助很小；继续进行测试、也就是主动从记忆中提取，效果明显更好。[Science 论文](https://doi.org/10.1126/science.1152408)

产品含义：

- 词卡不能只做“英文—中文翻面”和选择题；
- 看完释义后，应让用户根据中文、语境空格、音频或定义主动说出目标表达；
- Discussion 应要求用户使用本课 1–2 个表达，而不是只判断观点有没有道理；
- 纠错后必须有一次 **Try again / 再说一次**，否则反馈只是被阅读，没有被编码成新输出。

### 2. 一次学会通常是错觉：复习要跨天、跨材料

Cepeda 等人的综述汇总了 184 篇文章中的 317 个实验，结论支持分散学习优于挤在一次完成，而且理想间隔与希望保持记忆的时长有关。[University of South Florida 论文页](https://digitalcommons.usf.edu/psy_facpub/1771/)

产品含义：

- 单课结束不是完成，而是创建后续复习任务；
- 可先采用简单的 1、3、7、14、30 天节奏，再根据表现动态调整；
- 最好的复习不是永远回到同一张卡，而是在后续新材料中再次遇到并使用旧表达；
- 产品需要一层跨内容的 **Learning Memory**，记录“见过、认得、能回忆、能使用”四种不同状态。

### 3. 数字语境释义有效，但要克制地出现

数字阅读研究表明，语境释义、词典、测验、音频和个性化推荐都能支持词汇学习；研究也强调词汇学习是渐进的，识别通常早于主动回忆，新词需要多次相遇。[数字阅读词汇学习元分析](https://link.springer.com/article/10.1007/s10639-023-11969-1)

产品含义：

- 保留英境现有的逐词 hover、语境释义、原句和时间戳，这是非常正确的入口；
- 不要默认高亮所有生词。每个材料精选 **5–8 个核心词 + 2–4 个高价值词块** 即可；
- 用户点击过的词不应一律加入生词本，应结合频率、用户目标、内容中心性和复现价值排序；
- 先允许用户猜，再展开释义，比立即展示中文更有学习价值；
- 对视频，字幕应按需提供：英文字幕优先，中文翻译作为支架，而不是永久占据注意力。

### 4. 视频字幕有帮助，但“看懂”与“听懂”要分开训练

字幕视频研究整体支持字幕对二语听力理解和词汇学习的帮助；但如果用户始终依赖文字，可能练成阅读字幕而不是处理语音。[字幕视频元分析](https://www.sciencedirect.com/science/article/pii/S0346251X13001012)

产品含义：

- 同一片段可有三遍：首遍无中文获取大意；第二遍英文字幕精听；第三遍关闭字幕复听；
- 支持按句暂停、回放、0.75–1.0 倍速、关键片段循环；
- 加入听写、关键词捕捉、句子排序和 shadowing，而不只是双语字幕；
- 将“我看懂了”和“我听出来了”记录为两个独立进度。

### 5. 对话本身不够：AI 必须会追问、提示和选择性纠错

课堂研究的元分析表明，口头纠正反馈能产生显著且较持久的效果；要求学习者自己修正的 prompt，整体效果比只把正确句子重述一遍的 recast 更大。[Cambridge：口头纠正反馈元分析](https://www.cambridge.org/core/journals/studies-in-second-language-acquisition/article/abs/oral-feedback-in-classroom-sla/4999EE1C8379B2BF026B148EAF373CA1)

2024 年一项汇总 49 项研究、79 份报告的元分析也发现，AI 干预整体能改善语言学习结果，个性化、适应性和多来源反馈更有潜力；同时，研究之间差异很大，说明“用了 AI”本身不是教学法。[System：AI 与二语学习元分析](https://www.sciencedirect.com/science/article/abs/pii/S0346251X2400280X)

产品含义：

- AI 不应只说 “Great answer” 后问下一道预设题；
- 追问必须引用用户刚才的观点、原材料中的证据或本课目标表达；
- 优先用提示让用户自修，例如：“这里需要过去时，你想再试一次吗？”；
- 不要每句打断。交流期间只处理影响理解或本课目标相关的错误，每 2–3 轮集中反馈 1–2 个最值得修正的问题；
- AI 的话要短，把说话时间留给用户；语音会话中可把“用户发言占比 70% 左右”作为体验目标，而不是硬性评分。

### 6. 一套完整课程要平衡输入、输出、语言聚焦和流利度

Paul Nation 的 Four Strands 框架主张平衡四类学习：意义导向输入、意义导向输出、语言形式学习和流利度发展。[Victoria University of Wellington 资料](https://www.wgtn.ac.nz/lals/resources/paul-nations-resources/paul-nations-publications/publications/documents/What-Should-Every-ESL-Teacher-Know-13-Feb-2013.pdf)

这可以成为英境的课程质量检查器：一份自动生成的课不能只有生词和阅读，也不能只有随意聊天。

| 学习维度 | 在英境中的对应设计 |
| --- | --- |
| 意义输入 | 阅读文章、观看视频、听播客、理解主旨与证据 |
| 语言聚焦 | 核心词汇、词块、发音、句型、语用与语法微讲解 |
| 意义输出 | Discussion、角色扮演、复述、观点表达、写作 |
| 流利度 | 重复回答、限时复述、shadowing、同任务二次挑战 |

## 四、建议的产品形态：一份材料，三种学习深度

用户并不总想“上一整节课”。如果所有材料都强制经历十个环节，产品很快会变重。因此建议在导入后提供三条路径：

### 快速模式（约 5 分钟）

- 获取主旨；
- 学 3 个核心表达；
- 回答 1 个 Discussion 问题；
- 获得 1 条反馈；
- 创建轻量复习。

适合刷到一个短视频或临时读一篇网页时使用。

### 标准模式（约 15–25 分钟，默认）

- 学前预测；
- 一次整体输入；
- 5–8 个词、2–4 个词块；
- 3 个理解题；
- 3–5 轮 AI Discussion；
- 1 个 Further Discussion 任务；
- 反馈、重说、总结与复习。

### 深度模式（约 30–45 分钟）

- 分段精读或精听；
- 听写、shadowing、句型与语用观察；
- 多立场讨论、辩论或角色扮演；
- 口头复述 + 短写作；
- 延迟复做计划。

三种模式共享同一份学习记录，用户可以快速开始，之后再升级到深度学习。

## 五、标准课的完整学习流程

### Step 0：导入与诊断

支持四类入口：

- 当前视频或网页一键“变成英语课”；
- 粘贴 URL；
- 粘贴文字或上传字幕、音频、视频；
- 从历史观看或收藏内容中选择。

系统先生成一张 **Lesson Brief**：

- 内容主题、来源、时长或字数；
- 预估难度及“为什么难”；
- 用户已知词覆盖率；
- 推荐学习时长；
- 本课最值得掌握的语言目标；
- 对材料可靠性、字幕质量或转写质量的提示。

如果材料太长，系统不应该粗暴总结整份内容，而应按语义和时间轴切成 3–8 分钟的视频章节或 300–700 词的文章章节。每次只编译一个可完成单元。

### Step 1：Preview / 学前激活

目的不是教知识，而是激活背景知识并制造理解目标。

可自动生成：

- 看标题或缩略图预测内容；
- 选择你已经知道的相关词；
- 回答一个低门槛个人问题；
- 提醒用户首遍只抓主旨，不必查每个词。

### Step 2：First Pass / 首次输入

文章：先连续阅读一遍，默认不弹出中文。<br>
视频：首遍关闭中文，可按水平选择无字幕或英文字幕。<br>
播客：先听一段，再显示转写。

结束只问 1–2 个大意问题，例如：

- What is the main point?
- What changed from the beginning to the end?
- Which statement best describes the speaker’s attitude?

这一步要防止用户一开始就陷入逐词查阅。

### Step 3：Language Focus / 可学单词与表达

不建议标题叫“生词表”，而可叫 **Words & Phrases Worth Keeping**。筛选分数可由以下信号组成：

`学习价值 = 水平适配 + 内容中心性 + 通用频率 + 搭配价值 + 用户目标 + 未来复现概率 - 已掌握度`

每个学习项至少包含：

- 原形、词性、音标和音频；
- 当前语境中的中文义与简明英文释义；
- 原句、上下文和视频时间戳；
- 常用搭配或完整词块；
- 正式度、语气和常见使用场景；
- 一道主动提取题；
- 一个需要用户自己完成的个性化例句。

重点应从单词逐步转向 **词块**，例如不只收藏 `exposure`，还收藏 `be exposed to`；不只收藏 `evidence`，还收藏 `there is growing evidence that ...`。真实口语输出依赖可直接调用的表达单元。

### Step 4：Comprehension / 理解检查

题目应覆盖不同深度，而不是全部做事实选择题：

1. **事实提取**：谁、做了什么、结果是什么；
2. **推断**：作者为什么加入这个例子；
3. **立场与语气**：作者是支持、质疑还是保持谨慎；
4. **证据定位**：哪一段或哪句话支持你的判断；
5. **信息缺口**：材料没有回答什么。

系统应区分“内容理解错误”和“英语表达错误”。用户观点可以和 AI 不同，只要能用材料或逻辑支持，就不该被判错。

### Step 5：Discussion / 围绕材料的 AI 对话

Discussion 的目标是把刚理解的内容变成可表达的观点。建议采用“问题阶梯”，而不是一次生成十道静态题：

1. **Recall**：用自己的话说出材料主张；
2. **Interpret**：解释某个原因或影响；
3. **React**：表达同意、惊讶或质疑；
4. **Support**：给理由、例子或引用材料证据；
5. **Challenge**：回应反方观点；
6. **Synthesize**：总结更细致的结论。

AI 每次只问一个问题，并根据回答动态选择下一步。不会回答时提供三级脚手架：

- Level 1：给思路提示；
- Level 2：给关键词或句型开头；
- Level 3：给两种可选表达，但仍要求用户自己组织最终答案。

推荐内置四种 AI 身份：

- **Conversation Partner**：自然聊天，以流利度和信心为主；
- **Socratic Tutor**：连续追问理由、证据和反例；
- **Language Coach**：更关注目标表达和可理解性；
- **Examiner**：按 IELTS/面试/演讲等标准追问和反馈。

### Step 6：Further Discussion / 脱离材料后的迁移

Further Discussion 不能只是“更多相似问题”。它的任务是把语言和观点迁移到新场景。可以从以下任务族中选择一个：

- **Personalize**：联系自己的经历、家庭、城市或工作；
- **Role-play**：扮演顾客与员工、医生与家长、记者与研究者；
- **Debate**：AI 持相反立场，用户必须说服它；
- **Problem solving**：共同制定方案并权衡代价；
- **Teach-back**：向一个不懂该主题的人解释；
- **What if**：改变一个条件，推演结果；
- **Media literacy**：区分事实、推断、标题措辞和未被证明的结论；
- **Create**：生成一个标题、短演讲、社交媒体回复或后续采访问题。

这样，Discussion 负责“理解后的表达”，Further Discussion 负责“脱离原文后的迁移”。两者在学习目标上真正不同。

### Step 7：Feedback → Repair → Repeat / 反馈、修正与重说

每次会话结束后生成一张简短的 **Coach’s Note**：

- 你表达得最好的一点；
- 最影响自然度或准确度的 1–3 个问题；
- 原句 → 更自然表达 → 简短原因；
- 本课成功使用的目标表达；
- 一个 30–60 秒的“再说一次”任务。

反馈必须可操作。不要只给抽象分数，也不要一次列出十几个小错误。重说时隐藏完整答案，只保留关键词提示；系统比较两次表现，突出实际改善。

语音场景可分别观察：

- 可理解度；
- 语速与不必要停顿；
- 重音和节奏；
- 目标音或目标词；
- 语法、词汇和话语组织。

口音不应按“像不像某一种母语者”评分，首要目标是可理解、稳定和适合场景。

### Step 8：Retell / 复述与总结

复述是非常适合连接理解、词汇和口语的终局任务：

- 初级：使用给定关键词复述 3 句；
- 中级：60 秒概括“背景—发现—意义”；
- 高级：概括后加入限制、反方或自己的判断；
- 视频：先 shadow 关键句，再脱稿复述同一信息。

同一任务可以在会话末尾立即做一次，2–3 天后再做一次。任务重复研究支持其对二语流利度发展的作用。[Cambridge：口语任务重复研究](https://www.cambridge.org/core/journals/studies-in-second-language-acquisition/article/abs/task-repetition-and-second-language-speech-processing/0EA95A4C7D9E90CD2AB30043F84A4635)

### Step 9：Review / 间隔复习

复习队列不应只有词卡，而应混合四种记忆：

- **Form**：听到或看到后识别；
- **Meaning**：根据语境回忆含义；
- **Use**：补全搭配或完成句子；
- **Transfer**：在一个新问题中主动使用。

复习内容可包括：

- 回到原视频 8 秒片段，听出目标词块；
- 根据中文或定义说出表达；
- 修复自己上次说错的句子；
- 用旧表达回答一篇新材料的问题；
- 30 秒重新复述旧材料。

## 六、不同材料不应套同一模板

| 材料类型 | 最重要的学习能力 | 应强化的练习 |
| --- | --- | --- |
| 新闻/普通文章 | 主旨、证据、立场、词汇 | 标题预测、证据定位、事实与观点、Discussion |
| 影视/访谈视频 | 听力、口语语块、语气 | 分段精听、字幕切换、shadowing、角色扮演 |
| 播客 | 连续听力、信息组织 | 关键词笔记、章节总结、听后复述 |
| 短视频 | 快速口语、俚语、语用 | 逐句拆解、语气模仿、改写标题、真假判断 |
| 演讲/课程 | 结构化理解、学术表达 | 纲要、概念解释、teach-back、提问 |
| 对话/会议 | 轮次管理、功能语言 | 澄清、打断、同意/反对、会议角色扮演 |
| 论文/专业材料 | 精读、术语、论证 | 摘要重写、方法与结论区分、批判性问题 |

AI 先识别材料体裁和交际功能，再选择练习模板。产品应有“共享骨架 + 类型插件”，不应让所有视频最后都回答同一组泛泛的问题。

## 七、个性化系统：真正的壁垒不在生成，而在记忆

单次生成词表和问题很容易被复制。英境更有价值的壁垒是长期积累的学习者模型：

### 需要记录的用户状态

- 英语水平与目标场景；
- 认识、正在学、能回忆、能主动使用的词和词块；
- 常见语法、发音和语用问题；
- 容易理解但不容易说出的被动表达；
- 喜欢的主题、内容长度和学习时间；
- 使用过的脚手架等级；
- 每次回答原文、反馈和重说版本。

### 内容推荐不只看兴趣，也看“可学性”

推荐分数可同时考虑：

- 用户是否真的感兴趣；
- 已知词覆盖率是否足以理解；
- 是否自然复现最近正在学的表达；
- 是否补足长期薄弱项；
- 难度是否比当前能力高一点但不至于挫败；
- 是否包含可迁移到用户目标场景的语言。

最终形成一个很有辨识度的体验：**用户还是在看自己喜欢的内容，但系统悄悄让下一份内容成为上一课的复习。**

> **以用户自己的真实内容为中心，把四类能力组织成同一条学习闭环。**

## 九、结合英境现状的产品架构

英境已经具备视频字幕捕获、双语显示、高难词提示、语境查词、生词收藏和原句上下文，这是课程编译器非常好的 Capture Layer。下一步可分为五层：

### 1. Capture Layer / 内容层

- 网页正文抽取；
- TextTrack、WebVTT、TTML 和字幕 DOM；
- 合法可用情况下的音频转写；
- 标题、来源、时间戳、章节、说话人和原始上下文。

### 2. Lesson Compiler / 课程编译层

输入标准化内容和用户模型，输出结构化 Lesson JSON：

- 难度与章节；
- 学习目标；
- 核心词与词块；
- 主旨、理解与证据题；
- Discussion 问题阶梯；
- Further Discussion 任务；
- 反馈 rubric；
- 复述任务与复习计划。

生成内容必须保存原文 span 或视频时间戳作为依据，避免词义、问题和解释脱离材料。

### 3. Tutor Runtime / AI 教练层

- 管理会话状态，而不是一次生成整份聊天；
- 根据用户回答决定追问、提示、纠错或升级难度；
- 控制 AI 发言长度；
- 保持“交流模式”和“教练模式”的切换；
- 在会后生成可验证的反馈与重说任务。

### 4. Learning Memory / 学习记忆层

- 词、词块、错误模式和掌握状态；
- 原始材料与所有复现位置；
- 间隔复习调度；
- 从识别到主动使用的状态迁移。

### 5. Experience Layer / 体验层

- 视频上方的轻量学习入口；
- 独立 Lesson 页面承载标准课；
- 移动端适合语音讨论与短复习；
- 单词本升级为“表达库”，同时展示词、词块、原片段和自己的例句。

## 十、建议的 MVP 优先级

### P0：先跑通一条闭环

1. 当前文章或当前视频点击“生成课程”；
2. 自动分段、难度诊断和 Lesson Brief；
3. 5–8 个核心词 + 2–4 个词块；
4. 主旨题与 3 个分层理解题；
5. 基于材料的文字/语音 AI Discussion；
6. 一个可选择的 Further Discussion 任务；
7. 会后 1–3 条反馈、重说和保存复习；
8. 1、3、7 天的语境提取复习。

如果资源有限，P0 宁可只支持“有可靠英文文本或字幕的内容”，也不要过早承诺所有网站和所有视频。课程质量比导入覆盖面更重要。

### P1：让学习真正个性化

- 学习者词汇与错误模型；
- 自动调整问题和脚手架难度；
- 视频精听、听写、shadowing；
- 口语流利度与可理解度反馈；
- 旧表达在新材料中的自动复现；
- 快速、标准、深度三种模式。

### P2：形成内容与学习网络

- 多材料主题课程；
- 用户公开分享“课程配方”，不复制受版权保护的原内容；
- 教师编辑 AI 生成课程；
- 小组讨论或真人教师接管 AI 会话记录；
- IELTS、商务、面试、旅行等目标型 rubric。

## 十一、用参考文章主题做一个示例

以下只以“家中狗携带的微生物与婴儿健康”这一标题主题演示课程形态，不替代对原研究和原文事实的核验。

### Words & Phrases Worth Keeping

- microbe
- immune system
- exposure
- be associated with
- reduce the risk of
- build up immunity

### Comprehension

1. What is the study’s main claim?
2. What kind of relationship does the article describe: cause, correlation, or possibility?
3. Which detail in the article provides the strongest support for the claim?
4. What information would you still need before changing a family’s behavior?

### AI Discussion

**AI:** In your own words, why might living with a dog affect a baby’s health?<br>
**用户回答后动态追问：** You said early exposure may help the immune system. What evidence from the article supports that idea?<br>
**词汇脚手架：** Try using “be exposed to” or “be associated with.”<br>
**反方挑战：** Could there be another explanation for the result?

### Further Discussion

任选其一：

- **角色扮演：** 你是儿科医生，AI 是担心新生儿与宠物接触的家长；
- **辩论：** “Families with babies should be encouraged to keep a dog.”；
- **研究设计：** 设计一个更能区分相关性和因果关系的后续研究；
- **个人迁移：** 你成长环境中的宠物观念和文章中的观点有何不同？

### Feedback & Retry

- 重点反馈：`expose` 的被动结构、`evidence` 的不可数用法、表达谨慎结论时的 `may / might / be associated with`；
- 重说任务：用 45 秒概括研究主张，同时加入一个限制条件和自己的观点；
- 三天后复习：听到原片段后说出 `be exposed to`，再用它回答一个与宠物无关的新问题。

## 十二、衡量产品是否真的让人学会

不建议把“生成了多少课程”“收藏了多少单词”当核心指标。它们衡量的是生产和囤积，不是学习。

建议的北极星指标：

> **每周在延迟复习或自由讨论中被用户正确主动使用的已学表达数。**

关键过程指标：

- 导入材料后 20 秒内能否进入第一个学习动作；
- 课程生成后实际开始率；
- 首遍理解与辅助后理解的提升；
- Discussion 中用户发言时长与轮次；
- 反馈后的重说完成率和改善率；
- 1 天、7 天的意义回忆和主动使用率；
- 旧表达在新材料中的成功复用；
- 快速、标准、深度模式的复访与完成情况。

内容质量需要单独评测：

- 词义是否符合具体语境；
- 目标词是否真的有学习价值；
- 问题是否能在原材料中找到依据；
- Discussion 是否真正响应用户回答；
- 纠错是否准确、重要且适合用户水平；
- 难度判断与人工教师是否一致；
- 字幕、转写和说话人分段是否可靠。

## 十三、主要风险与设计约束

### 1. AI 生成错误

词义、研究结论、问题答案和语法解释都可能出错。所有内容型题目应绑定原文证据；AI 不确定时要明确表达不确定，而不是补全事实。高风险专业内容不能把语言练习包装成医疗、法律或投资建议。

### 2. 认知负担过高

双语字幕、高亮、词卡、问题和聊天同时出现会把内容体验压垮。默认界面只显示当前任务，帮助按需展开。学习层应能随时收起，让用户重新回到内容本身。

### 3. AI 过度纠错

逐句纠错会让用户不敢说。需要让用户选择“流利优先、平衡、准确优先”，并坚持一次只修最有价值的问题。

### 4. 语音识别与口音偏差

ASR 没听懂不等于用户发音错误。低置信度时应让用户重录或查看转写，不能直接给出负面评分。

### 5. 版权、平台条款与隐私

产品应优先在用户浏览器内处理用户正在合法访问的内容，保存学习笔记、时间戳和必要片段引用，而不是建立未经授权的全文或视频副本库；对上传内容、语音记录和第三方模型传输提供清楚的同意与删除机制。具体上线地区仍需正式法律审查。

### 6. 网页内容安全

导入的网页文本是不可信输入。课程编译器需要把网页内容严格当作学习材料数据，隔离其中可能诱导模型执行操作、泄露信息或改变系统规则的指令。

## 十四、第二轮推演：课程不是终点，而是一次能力状态变化

第一轮方案仍然容易把产品理解成“给内容生成一套练习”。继续往深处看，真正应该交付的不是 Lesson 页面，而是一次可验证的状态变化：

> **学习前，用户只能看懂或听懂某种表达；学习后，他能在另一个场景中不依赖原文主动使用它。**

因此，每次生成课程前，系统都应该先建立一个很短的 **Learning Contract（学习契约）**：

- 学完后你应该能解释什么；
- 你应该能使用哪 2–4 个表达动作；
- 你将在什么新情境中证明自己真的会了；
- 系统用什么证据判断这次学习完成。

例如，一篇研究类新闻的学习契约可以是：

> 学完后，用户能用 60 秒概括研究主张，用 `be associated with` 谨慎描述相关关系，并能指出报道没有证明因果关系。

这样，词表、理解题、Discussion、反馈和复习都服务于同一个能力目标，而不是相互独立的模块。Lesson Compiler 也不再是“内容生成器”，而成为 **目标—活动—证据的编排器**。

一个课程对象至少应包含：

```text
Learning Contract
├── Comprehension outcome：能够理解什么
├── Communicative moves：能够用语言完成什么动作
├── Practice path：需要经历哪些输入、提取和互动
├── Evidence：怎样证明当下学会
└── Delayed transfer：几天后怎样证明仍然会用
```

## 十五、真正的学习单元：从“单词”升级为“表达动作”

### 为什么单词太小、课程又太大

- 单词是词典单位，却不一定是沟通单位；知道 `evidence` 不等于会说 `There is little evidence that ...`。
- 一篇课包含太多东西，无法准确回答用户究竟掌握了什么。
- 句子虽然完整，但常常只适用于原文；整句背诵不一定能迁移。

更适合英境的最小单位是 **Communicative Move（表达动作）**：一个语言形式，加上它完成的意图、适用场景和用户使用证据。

| 表达动作 | 可能的英语形式 | 可迁移场景 |
| --- | --- | --- |
| 谨慎描述关系 | be associated with; may be linked to | 新闻、研究、工作汇报 |
| 要求澄清 | What do you mean by…?; Are you saying that…? | 对话、会议、课堂 |
| 提出反例 | That may be true, but…; One counterexample is… | Discussion、辩论、写作 |
| 保留意见 | I’m not entirely convinced that… | 商务、学术、日常讨论 |
| 组织解释 | The main reason is…; Another factor is… | 面试、演讲、考试 |
| 修正自己 | Let me rephrase that.; What I meant was… | 所有真实口语场景 |

表达库因此不应只按 A–Z 或“已收藏单词”展示，而应允许用户按功能查找：

- 表达观点；
- 同意与反对；
- 澄清和确认；
- 比较与让步；
- 解释原因；
- 描述不确定性；
- 讲故事；
- 管理会议或对话轮次。

每个表达动作的掌握记录包括：

- 在哪些真实材料中遇到过；
- 是否能识别和解释；
- 是否在提示下使用过；
- 是否曾经无提示主动使用；
- 在几种不同话题或场景中使用过；
- 最近一次成功和失败的证据；
- 仍然常见的搭配、语法或发音问题。

这会把英境的“单词本”自然升级为 **个人表达能力地图**。

## 十六、AI 最重要的教学能力：管理“什么时候不帮”

生成解释、翻译和示范答案，是模型最容易做到的事，也是学习产品最容易做过头的事。帮助太少会挫败，帮助太多会让用户产生“我已经会了”的流畅错觉。

“desirable difficulties”相关研究强调，提取、间隔、变化和一定程度的努力有助于长期学习，但难度也可能变成纯粹阻碍，必须与学习者状态匹配。[Desirable Difficulties in Vocabulary Learning](https://pmc.ncbi.nlm.nih.gov/articles/PMC4888598/)

因此，英境需要的不是一个 Help 按钮，而是一套 **Assistance Budget（帮助预算）**。

### 帮助阶梯

```text
0. 独立尝试
1. 再听一次 / 再看上下文
2. 给意义方向或首字母
3. 给关键词、句型骨架或二选一
4. 展示完整示范
5. 隐藏示范，要求用户重新提取和表达
```

关键规则是：**只要系统给过完整答案，这笔帮助就要在后续通过一次独立提取“偿还”。**

产品可以为每个用户动态维护一个 **Friction Dial（学习摩擦旋钮）**：

- 连续轻松成功：减少字幕和提示，增加迁移距离；
- 能理解但输出很慢：保留内容难度，提供表达骨架；
- 内容也没理解：先降低材料或分段，不急着要求自由讨论；
- 频繁依赖中文：逐步延迟翻译出现时间，而不是突然关闭；
- 反复犯同类错误：缩小任务，只练一个表达动作后再回到对话。

这也意味着“个性化”不能只表现为 AI 说出用户名字或推荐喜欢的话题，而应体现为：**在正确时刻撤掉正确的一层支架。**

## 十七、把 AI Discussion 设计成“意义协商”，而不是智能问卷

ICAP 框架把学习参与从 Passive、Active、Constructive 到 Interactive 分为不同层次，并提出更深的认知参与通常带来更好的学习结果。[ICAP 原始论文](https://www.tandfonline.com/doi/abs/10.1080/00461520.2014.965823)

对应到英境：

| 行为 | ICAP 层次 | 产品例子 |
| --- | --- | --- |
| 看视频、读翻译 | Passive | 观看双语字幕 |
| 点词、划线、收藏 | Active | 保存 `be exposed to` |
| 自己概括、造句、解释 | Constructive | 用目标表达总结研究 |
| 与 AI 协商、澄清、辩护、修正 | Interactive | 回应反例并重构观点 |

点击、收藏和完成选择题看起来很“互动”，但认知上可能仍然很浅。每个标准课程应至少包含一次 Constructive 行为和一次真正的 Interactive 行为。

二语互动研究认为，有效互动包含输入、输出、注意、纠正反馈和 negotiation for meaning；当沟通发生不清楚时，澄清请求、确认检查和修改输出本身就是重要学习机会。[Cambridge：Interaction and Instructed SLA](https://www.cambridge.org/core/journals/language-teaching/article/interaction-and-instructed-second-language-acquisition/78A156EE200F744F5978F99BFB073DBE)

因此，AI Discussion 不应永远“理解”用户，也不应把含糊、断裂的表达自动脑补成正确意思。它可以自然地做三种协商：

- **Clarification request**：`What do you mean by “healthier” here?`
- **Confirmation check**：`Do you mean the microbes caused the result, or were only associated with it?`
- **Comprehension check**：`Would you like me to rephrase the question?`

这不是故意刁难用户，而是给表达制造真实后果：如果信息不够清楚，对话伙伴需要用户补充、改写或举例。

### 建议的对话状态机

```text
Ground in source
      ↓
Invite an answer
      ↓
Evaluate meaning + language + target move
      ↓
┌─────────────┬──────────────┬───────────────┐
│ Meaning clear│ Meaning vague │ Learner stuck │
│ Probe/Challenge│ Clarify/Confirm│ Scaffold     │
└─────────────┴──────────────┴───────────────┘
      ↓
Prompt self-repair when valuable
      ↓
Transfer the same move to a new context
      ↓
Save evidence and schedule delayed reuse
```

这套状态机要由结构化策略控制，而不能完全依赖一个长 prompt 临场发挥。AI 可以生成语言，但产品必须决定此刻的教学动作。

### 让用户解释自己的思路

除了回答问题，还可以要求用户解释：

- 你为什么选择这个答案；
- 哪一句原文让你这样判断；
- 你的第二次说法比第一次改进在哪里；
- 这个表达还可以用在什么场景。

数字学习环境中的自我解释研究汇总 56 项研究、204 个效应量，发现自我解释对即时、延迟和迁移表现均有正向作用；由学习者控制节奏的环境效果更好。[ERIC：自我解释元分析](https://eric.ed.gov/?id=EJ1461751)

## 十八、解决“看内容”和“学英语”的天然冲突

英境当前从视频切入，这里存在一个核心矛盾：用户选择影视内容通常是想沉浸和享受，而语言学习需要暂停、回忆和失败。如果学习层持续打断，用户会关闭它；如果完全不打断，又很难发生深度学习。

建议把产品明确分成三种消费—学习关系：

### 1. Immerse / 沉浸模式

- 不中断播放；
- 只提供按需字幕和 hover 查词；
- 系统在后台收集高价值片段、用户查过的词和潜在难点；
- 结束后生成一份 3–5 分钟的 **After-watch Capsule**。

这是默认娱乐模式，承诺“先享受内容”。

### 2. Guided / 引导模式

- 每个章节只出现 1–2 个学习时刻；
- 在自然场景切换或暂停时提问；
- 优先做预测、听辨和一句复述；
- 用户可以一键跳过，不制造完成压力。

适合纪录片、访谈、课程视频和明确学习目的的观看。

### 3. Studio / 精学模式

- 逐句播放、循环、字幕切换；
- 听写、shadowing、语气模仿；
- 用户替换角色台词，与 AI 演完整场景；
- 允许反复录音、比较和重做。

适合用户主动收藏的片段，不适合强加给整集影视内容。

这三种模式比“始终显示多少辅助”更接近用户当下意图。用户可先沉浸，之后再学习；同一个内容对象不必在第一次观看时完成所有教学动作。

### 视频独有的高价值学习方式

- **Voice Swap**：AI 扮演角色 A，用户接角色 B 的台词；
- **Semantic Shadowing**：不逐字复读，而是用自己的话保持相同含义和语气；
- **Emotion Replay**：用生气、犹豫、礼貌、讽刺等不同语气表达同一句意图；
- **Alternate Line**：为角色生成另一句自然但功能相同的台词；
- **Scene Branching**：改变用户一句回答，让 AI 延续新的剧情；
- **Pragmatics Lens**：解释一句话为什么在这个关系和场景中显得礼貌、强硬或讽刺；
- **No-subtitle Boss Round**：学完后关闭字幕完成同片段理解和角色回应。

这些能力比单纯的双语字幕更难被普通播放器复制，也更能利用英境已经掌握的时间轴和上下文。

## 十九、Learning Memory 应该是一张证据图，而不是复习队列

传统 SRS 往往把每张卡视作独立项目；但真实语言知识由表达、意图、搭配、声音、场景、话题和错误模式相互连接。建议把学习记忆设计成一张 **Evidence Graph（掌握证据图）**。

### 核心节点

- Expression：单词、词块、句型；
- Communicative Move：表达承担的功能；
- Meaning/Sense：具体语境义；
- Content Moment：原文 span 或视频片段；
- User Attempt：用户实际说过或写过的版本；
- Error Pattern：语法、搭配、发音和语用问题；
- Scenario：工作、旅行、学术、日常等场景；
- Goal：面试、看剧、会议、考试等个人目标。

### 掌握状态不是二元值

```text
Seen
  → Recognized in context
  → Recalled with a cue
  → Used with a scaffold
  → Used independently
  → Used spontaneously
  → Generalized across topics/registers
```

升级必须由行为证据触发，不能因为用户点击“认识”就直接标记掌握。不同证据权重也应不同：

- 看见后选择正确 < 根据定义回忆；
- 照着句型填空 < 自由回答中主动使用；
- 原话题复述 < 在新话题中自然迁移；
- 当场成功 < 数天后无提示成功。

### 从复习推送升级为“内容中的自然回声”

当用户打开新材料时，系统可以发现其中包含旧表达，并提示：

> `be associated with` 又出现了。这是你第三次在不同话题中遇到它。

或者在新 Discussion 中自然设计一个必须调用旧表达的追问。这样，复习不再是离开真实内容去完成卡片，而是旧知识在新内容中持续回响。

这会形成产品飞轮：

```text
更多真实内容
  → 更准确的兴趣与语言画像
  → 更好的目标选择和难度控制
  → 更多可验证的输出证据
  → 更准确的记忆与推荐
  → 下一份内容更有兴趣，也更“刚好可学”
```

真正难复制的数据不是用户看过哪些视频，而是：**他在哪些真实语境中，曾怎样尝试表达，接受什么提示后修正，后来又能否独立迁移。**

## 二十、产品战略：长期支持任意内容，短期必须选择一个楔子

“让任何英文材料变成课”是很好的长期愿景，却不是一个适合同时开工的产品范围。文章解析、流媒体字幕、播客转写、论文结构和短视频语用需要不同的内容链路与质量评测。

结合英境现状，最有优势的第一个楔子仍然是：

> **把用户刚刚看过并真正喜欢的一段视频，变成一份 5–15 分钟的课后学习胶囊。**

理由是：

- 英境已经有字幕、时间轴、上下文、查词和收藏行为；
- 场景、人物、声音和情绪提供比普通词卡更强的记忆线索；
- “看完再学”比播放中频繁打断更容易被接受；
- 基于同一片段做听力、词块、角色扮演和复述，产品辨识度高；
- 当视频闭环成立后，文章只是更稳定、更便宜的第二类输入。

### 推荐的首个核心体验

```text
用户看完一段视频
  → 弹出“用刚才的内容练 5 分钟”
  → 回听 2 个关键片段
  → 学 3 个表达动作
  → 与角色或 AI 讨论 3 轮
  → 修正并重说 1 次
  → 三天后在新问题中重新使用
```

### 应明确延后的功能

- 自动生成二十道题的“练习大全”；
- 为所有未知词生成卡片；
- 没有材料依据的通用 AI 自由聊天；
- 把口音压成一个“像母语者程度”总分；
- 只靠连续签到和积分维持使用；
- 在用户尝试前展示标准答案或完整范文；
- 同时支持所有网站、所有文件和所有内容类型；
- 过早建设课程社区或社交网络；
- 建立未经授权的完整影视、文章内容库。

这些功能有的最终可以存在，但不应抢占“输入—输出—反馈—延迟迁移”闭环的资源。

### 产品壁垒判断

| 能力 | 容易复制程度 | 长期价值 |
| --- | --- | --- |
| 生成词表和问题 | 很容易 | 低 |
| 双语字幕和点击查词 | 中等 | 入口价值高 |
| 稳定捕获跨网站内容语境 | 中等偏难 | 高 |
| 基于回答动态选择教学动作 | 较难 | 高 |
| 精确记录表达掌握证据 | 难 | 很高 |
| 用未来内容自然复习过去内容 | 很难 | 很高 |
| 证明用户在延迟迁移中进步 | 很难 | 最高 |

模型本身不会成为壁垒；围绕模型建立的教学状态机、内容锚点、学习证据和长期反馈循环才可能成为壁垒。

## 二十一、值得实验的高潜力创意

以下创意不应同时开发，但适合逐个做低成本原型和用户测试。

### 1. After-watch Capsule / 看后胶囊

系统根据用户刚才查过、回放过和停留过的片段，自动生成个性化五分钟学习。它比通用总结更贴近用户实际困难。

### 2. Memory Lens / 记忆透镜

用户浏览任意网页或字幕时，已经学过的表达出现一个低干扰标记：见过几次、上次在哪里、是否曾主动用过。点击可快速回忆原场景。

### 3. Future Callback / 未来回调

AI 在几天后的新 Discussion 中自然提出一个很适合调用旧表达的问题，但不提醒答案；成功后告诉用户这是一次跨话题迁移。

### 4. Reverse Lesson / 反向教学

让用户向 AI 解释材料。AI 扮演一个有合理误解的听众，通过澄清和反问迫使用户补足因果、例子与定义。目标不是让 AI 判答案，而是让用户把意思讲清楚。

### 5. Content Ladder / 同主题内容阶梯

系统围绕同一主题安排从简化内容到真实原生内容的阶梯，让背景知识和核心词汇重复出现，同时逐步撤掉辅助。

### 6. Same Meaning, New Register / 同义换场景

让用户把影视口语改成工作邮件、把新闻结论说给朋友、把正式演讲改成日常解释。重点训练语域，而不是只训练同义词。

### 7. Weekly Boss Round / 每周迁移挑战

提供一份用户没见过的短内容，不允许查完整翻译。要求理解、复述并讨论，用来测量真实迁移，而不是重复熟悉题目。

### 8. Language Fingerprint / 表达指纹

不只展示词汇量，而是显示用户能够完成哪些沟通动作：举例很强、表达不确定性不足、很少主动澄清、能够组织原因但不会让步等。

### 9. AI Rehearsal → Human Handoff

先与 AI 练习，再生成一张给真人教师或语言伙伴的 Conversation Card，包含材料、目标表达、用户困难和建议追问。AI 的定位是排练和记录，不是永久取代真人互动。

### 10. Personal Error Episodes / 个人错误片段

把用户自己的典型错误做成极短复习：播放当时的上下文、显示原说法、要求重构，再在不同内容中重新使用。自己的错误通常比通用语法题更有意义。

## 二十二、需要尽早验证的十个假设

功能优先级最终应由这些假设是否成立决定：

1. 用户愿意在看完内容后继续投入至少 3–5 分钟学习；
2. 用户认为“刚才真实内容里的表达”比通用课程更值得学；
3. 每课只学少量表达，比生成很多词和题更有完成感；
4. AI 基于回答动态追问，明显优于静态 Discussion 列表；
5. 用户可以接受 AI 偶尔请求澄清，而不把它视为模型能力差；
6. 反馈后立即重说，能带来用户可感知的改善；
7. 三天后回到原片段或新语境，不会被视为打扰；
8. 用户愿意让系统保存自己的回答和错误以换取个性化；
9. “表达动作地图”比传统单词本更容易让用户理解自己的进步；
10. 延迟迁移表现能够预测留存和付费意愿，而不只是增加测试负担。

每个假设都应该设计一个最小实验，不要等完整系统建好再验证。例如：先人工为 10–20 段视频制作看后胶囊，观察用户是否完成、是否重说、三天后是否愿意复用表达，再决定自动化架构。

## 二十三、收紧后的最小方案：3–2–1 学习闭环

前面的完整方案描述了长期产品，但首版不应实现一套完整“AI 学校”。如果只保留学习收益最高、用户阻力最低、最容易验证的部分，建议收紧成一个 **3–2–1 协议**：

> **3 个表达动作 → 2 次口语输出 → 1 次延迟迁移**

内容理解、词汇学习、AI Discussion、纠错和间隔复习都压缩进这三个数字中。

### 为什么是 3–2–1

- **3 个表达**足以形成明显收获，又不会把观看后的用户拖进一张长词表；
- **2 次输出**代表第一次真实尝试和反馈后的第二次重说，能让用户当场感受到改善；
- **1 次延迟迁移**用来区分“刚刚模仿成功”和“后来真的能够使用”。

如果只能做一个版本，就做这一个。其他理解题、词卡、角色模式、详细评分和学习地图都先不进入默认流程。

### 整个流程控制在 5–7 分钟

#### 0. Replay / 回到内容，30–60 秒

文章重新显示最关键的一段；视频回放 1–2 个总长不超过 30 秒的片段。只问一个问题：

> **What happened, why does it matter, and what do you think?**

它把主旨理解、意义解释和个人反应合并为一个输出任务，不再单独做五道理解题。

#### 1. Pick 3 / 学三个表达，60–90 秒

AI 只选择三个可以迁移的表达动作，不选择三个最难单词。每个表达只显示四项：

- 英文形式；
- 当前语境中的一句中文解释；
- 原句或原视频片段；
- 一个极短的可替换句型。

例如：

```text
be associated with
表示“与……相关”，不直接声称因果关系
The microbes were associated with better health outcomes.
X may be associated with Y.
```

不默认展示词源、全部义项、长篇语法说明、同义词列表或多个例句。需要时用户再展开。

#### 2. Speak #1 / 第一次输出，45–90 秒

用户直接回答前面的综合问题，目标是在自然表达中尽量使用 1–2 个新表达。AI 此时不打断，只做三件事：

- 判断意思是否清楚；
- 记录目标表达是否被正确使用；
- 找出一个最值得改善的问题。

第一次输出是真实基线，不应先给标准答案。

#### 3. Fix 1 / 只改一个关键问题，30–60 秒

AI 的反馈最多包含：

```text
You said: 用户原句
Try: 更清楚或自然的版本
Why: 一句中文原因
```

选择优先级：

1. 影响理解；
2. 本课目标表达使用错误；
3. 高频且可迁移的语法或搭配；
4. 明显不自然但容易修正的说法。

不处理无关紧要的小错误，不给综合分数，不同时评价发音、语法、词汇、流利度等十个维度。

#### 4. Speak #2 / 立即重说，45–90 秒

隐藏完整修改句，只保留三个目标表达和几个关键词。用户重新回答同一个任务，或者回答一个非常接近的问题。

完成后只展示两件事：

- 这次比第一次具体改善了什么；
- 哪些表达已经成功使用。

“重说”是默认完成动作，而不是反馈页上的可选按钮。

#### 5. Callback / 一次延迟迁移，第二天或第三天 30–60 秒

系统不再重问原材料内容，而是在一个新话题里要求用户使用其中一个表达动作。例如：

> 原材料讨论宠物与健康；延迟任务改为：`Do you think remote work is associated with better mental health? Why or why not?`

如果能够无提示使用，则形成一次有效迁移证据；失败时只回放原片段和一个提示，然后再次尝试。

### 一张页面就能完成

首版界面不需要复杂课程导航，可以只有四张依次展开的卡片：

```text
┌────────────────────────────┐
│ 1. Replay                  │
│ 原文关键段 / 关键视频片段   │
└────────────────────────────┘
              ↓
┌────────────────────────────┐
│ 2. Keep These 3            │
│ 三个表达动作                │
└────────────────────────────┘
              ↓
┌────────────────────────────┐
│ 3. Speak → Fix → Speak     │
│ 录音、一个反馈、立即重说     │
└────────────────────────────┘
              ↓
┌────────────────────────────┐
│ 4. Use It Later            │
│ 明天/三天后的新场景回调      │
└────────────────────────────┘
```

Discussion 与 Further Discussion 不再是两个长题库：

- 第一次 Speak 是 **Discussion**：围绕原材料理解和表达；
- 延迟 Callback 是最小版 **Further Discussion**：离开原材料做迁移。

### AI 只需要四个明确职责

首版不需要多个 AI 人格或复杂 agent。一个 Tutor Runtime 只做：

1. **Select**：选三个高价值表达动作；
2. **Prompt**：生成一个综合口语任务；
3. **Coach**：选择一个最高价值反馈；
4. **Transfer**：生成一个新的延迟使用场景。

每一步都输出结构化数据，并绑定原文 span 或视频时间戳。模型不需要自由决定整个教学流程。

### 个性化先只保留一个旋钮

首版不必建立完整学习者模型，只根据用户表现选择三档脚手架：

| 档位 | 展示方式 |
| --- | --- |
| Support | 中文解释 + 关键词 + 英文句型开头 |
| Standard | 简短中文解释 + 三个目标表达 |
| Challenge | 只给表达，不给句型；第二次输出增加新条件 |

系统根据第一次输出是否清楚、停顿和求助情况自动推荐，但用户可以随时手动切换。先验证“撤掉哪层帮助”是否有效，再建设复杂的水平诊断。

### 首版只保存最必要的学习证据

```text
source_id / source_span / timestamp
three_target_moves
attempt_1
one_feedback_item
attempt_2
callback_result
```

这六类数据已经足以回答最重要的问题：用户第一次怎么说、AI 改了什么、第二次是否改善、几天后能否迁移。完整 Evidence Graph 可以在这些真实数据积累后再设计。

### 默认不做的东西

- 不生成长词表；
- 不生成选择题题库；
- 不要求用户先做水平测试；
- 不提供无限自由聊天；
- 不一次纠正多个错误；
- 不展示复杂雷达图和总分；
- 不要求每天复习十几张卡；
- 不在视频播放过程中强制暂停；
- 不追求一开始支持所有材料类型。

用户如果想深入，可以展开词义、继续讨论或进入 Studio，但默认路径始终保持 3–2–1。

### 最小成功指标

首版只看四个指标：

1. **开始率**：看完内容后有多少用户愿意开始 3–2–1；
2. **重说率**：得到反馈后有多少用户完成第二次输出；
3. **即时改善率**：第二次是否修复目标问题或更好使用表达；
4. **延迟迁移率**：第二天或第三天能否在新语境中无提示使用。

课程生成量、收藏词数、AI 对话轮数和停留时长都不是首版核心成功指标。

### 一句话产品定义

> **英境从你刚看过的内容里挑出三个真正值得带走的表达，让你说一次、改一次，并在几天后真正用出来。**

## 二十四、最终建议

英境下一阶段最值得验证的不是“AI 能不能生成很多题”，而是 3–2–1 是否成立：

> **三个表达动作 → 第一次说 → 只改一个问题 → 第二次重说 → 三天后在新语境中用一次。**

如果这条链路成立，之后增加网站、题型、模型和课程模板都会放大价值；如果这条链路不成立，再多的自动生成内容也只会变成新的学习资料仓库。

产品层级也可以进一步收紧：

- **Learn This / 就学这个**：从当前内容开始；
- **Speak**：第一次输出；
- **Try Again**：反馈后重说；
- **Use It Later**：延迟迁移。

复杂能力仍然可以存在于展开项和后续版本中，但默认体验必须让用户无需理解教学术语，也能在几分钟内走完一次完整学习循环。
